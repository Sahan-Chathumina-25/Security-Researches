Methodology

How each audit is performed

A constant evidence chain across projects: pinned source → triaged analysis → controlled verification → patch validation → report.

  1. {% include icon.html name="git-branch" size="18" %}

    Source Acquisition

    Official upstream repositories at a pinned commit or tag, signatures verified where available.

  2. {% include icon.html name="book-open" size="18" %}

    Codebase Understanding

    Baseline builds and written architecture documents produced before any auditing begins.

  3. {% include icon.html name="network" size="18" %}

    Attack Surface Mapping

    Trust boundaries, process model, and privilege levels established for factual impact assessment.

  4. {% include icon.html name="search" size="18" %}

    Security Auditing

    Static analysis with every report triaged, plus deep manual review of parsing and memory-critical paths.

  5. {% include icon.html name="flask" size="18" %}

    Finding Verification

    Sanitizer builds, Valgrind cross-checks, purpose-built harnesses, and mandatory control experiments.

  6. {% include icon.html name="shield" size="18" %}

    Responsible Disclosure

    Confidential vendor reports held for official security policies; public docs redacted until patched.
